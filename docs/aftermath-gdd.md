# AFTERMATH｜「硅典-断桥」核心设定集

单聚落 MVP · 设计稿 0.1

## 1. 玩家体验

2051 年，第三次世界大战结束约二十年。无锡太湖西岸的「硅典-断桥」靠战前民防掩体、博物馆库存和一台还能转动的普通车床维持生计。居民能绕线、车削和翻修旧设备。先进芯片只能从有限的存货中替换，整机坏掉以后，聚落可能得换用功能更少的替代设备。威胁来自缺水、伤病、天气和设备失效，技术上限由本地工人、工具和备件决定。

玩家是一百名居民中的一名技术与账本架构师。每天看库存和设备记录，判断哪项服务最可能中断，提出供电、排产或维护方案，再看居民愿意接哪些班。居民保有拒绝的权利。方案的实际产出取决于到岗工时、设备状态、供电和备件。

**核心循环**：查账本 → 找瓶颈 → 提议班次与优先级 → 居民接受或拒绝 → 按规则结算 → 核对库存、设备与健康变化 → 调整次日计划。

一个典型选择是阴雨天将最后一档备用电给净水还是给车床。净水维持当天供给，车床能加工后续维修用的零件。玩家可以查出上一次断水究竟出在供电、设备、工时，还是储备耗尽，并据此安排次日工作。

## 2. 场景边界

一个聚落、一份共享库存账、100 名固定身份居民、500 个模拟日。地点通过设施、作业槽位和事件归属参与模拟，首版用列表或简单俯视区块呈现。

| 区块 | 聚落内的作用 | 首版交互 |
| --- | --- | --- |
| 地下核心区 · B1/B2 | 民防掩体与半导体/计算机博物馆改造的储藏、档案和计算区 | 查看仓储和离线账本，检查服务器与精密备件库存 |
| 丘陵坡地 · 旧广播站 | 光伏、风力和通信设施所在地 | 查看发电预期与设备状态，安排巡检 |
| 滨湖平地 · 断桥码头 | 公共灶、卫生站、机修棚、净水点、农田与近岸渔获 | 安排生产和维修，查看饮水、饮食与伤病记录 |
| 断桥附近 · 半淹没废墟边缘 | 聚落可直接抵达的旧设施与残料堆 | 回收预先列账的库存，耗尽后该作业槽关闭 |

短波是聚落对外联络的窗口。MVP 中广播站可以播报本地天气、设备停机和供给状态。远距离交易、跨区派遣和废墟副本留作后续扩展。

## 4. 居民与协调规则

- 居民拥有固定 ID、姓名、年龄、劳动能力、饥饿、缺水、疲劳和健康。每人每天最多接受一个班次。满足基本需求并休息可以恢复状态，缺给和工伤会减少次日可用工时。
- M0 的排产由聚落默认规则产生。先安排供水和食物，其次是达到维护条件的作业，再安排回收和休息。居民按能力匹配，候选相同时按 ID 排序。状态触发的拒绝记录具体原因，岗位空缺按实结算。
- 玩家可交互后，排产以提案方式进入账本，包含设施、名额、耗材和预计收益。居民依据健康、疲劳、能力、已承诺工时以及风险同意或拒绝。组织规则可以改变提案的优先级和批准条件。即使提案获批，每名居民仍单独决定是否接班。
- 聚落议事机构、生产合作组织、物资交换组织共享同一小地图。议事机构制定供给优先级，合作组织提出生产与维修班次，交换组织管理领用和回收。首个可玩的集体决策是修改应急电力使用规则。

## 5. M0 首轮调参基线

以下是原型初值，表达玩法比例。资源单位为整数，1 份食物或饮水对应一人的日配给。电力用当日负载点计量。开局有 20 名水务工、33 名农渔工、13 名机修工与 34 名通用工。水务、食物和维护岗位优先使用对应专长，再由通用工补位。通用工也可回收残料。同一居民一天只能占用一个岗位。

| 项目 | 初始规则 |
| --- | --- |
| 开局库存 | 食物 400、水 400、燃料 24、木材 8、钢材 8。现场木料与废钢按地块单独记账 |
| 季候 | 以 2051-04-01 为第 1 日按公历划分春夏秋冬。农田单产随季节变化：春季晴 6 阴 4、夏季晴 7 阴 5、秋季晴 8 阴 6、冬季晴 5 阴 4；近岸渔获不受季节影响。夏季为蓝藻期，原水水质下降 32 点，净水站多耗 1 点电 |
| 食物 | 每日最多 20 个班次，其中农田 13 班、近岸渔获 7 班。农场班按季节产出，渔获每班晴天 6 份、阴雨 4 份 |
| 净水 | 设备状况初值 70。状况高于 20 且分到 4 点电才开机。最多 14 个班次，每班产 10 份。出水后当天磨损 2 点 |
| 电力 | 晴天 14 点，阴雨 5 点。优先支付 2 点公共负载，再依次为具备工时和设备条件的净水、具备工时和建材条件的维护供电。仅当新增电量足以让当前作业运行时启用备用机组，每消耗 1 份燃料补 4 点，当日最多消耗 2 份。M0 当日剩余电力到日终清零 |
| 维护 | 水泵状况低于 60 时可派 1 人维护，消耗木材与钢材各 1 份及 2 点电，恢复 16 点设备状况，上限 100。钢材耗尽后改用木材 1 份的代用件，恢复 10 点、上限 80。先支付净水负载，再支付维护负载。当天维修，次日重新评估能否投产 |
| 回收 | 每天最多 2 人各搬运 1 份材料，封锁区除外。林地可采木料按雨天进度恢复，每次 2 份，单块上限 8 份；钢材回收受现场存量限制 |
| 医用耗材包 | 卫生站空闲班次备制，1 份清洁布料、1 份消毒用品和 1 份饮水合成 1 份医用耗材包，库存低于 8 份时补货，每天最多 2 份 |
| 配给 | 每位在世居民每天需求 1 份食物和 1 份饮水。短缺时，两项各用从当日轮转起点开始的居民 ID 循环顺序分配，次日起点移动一位 |
| 居民状态 | 需求与健康值限制在 0–100。开局健康 100，疲劳、饥饿与缺水为 0。工作疲劳 +12，休息疲劳 −20。吃饭使饥饿 −12，缺给 +20。喝水使缺水 −20，缺给 +35。疲劳 ≥70 或健康 ≤40 拒班 |
| 工伤和健康 | 每名到岗居民按班前疲劳抽取工伤，概率为 `1 + floor(疲劳 / 10)`%。受伤扣 15 健康，饥饿 ≥40 扣 4，缺水 ≥35 扣 8。足额进食和饮水并休息时恢复 5。健康降至 0 退出后续作业与配给 |
| 天气 | 每日用场景种子驱动的伪随机数判定，阴雨概率 25%。首轮通过长跑检查缺给与停机频率，再校准开局储备、产量和磨损 |

**每日结算顺序**从抽取天气开始。按日初状态排班，分配电力与燃料，结算生产和回收，记录设备磨损后再结算维修，接着配给物资、处理工伤和健康，最后输出日终摘要。日内投产资格使用日初设备状况。已接班但因供电或设备停工的居民转为休息。每日日终按居民 ID 顺序结算随机工伤，配给的轮转顺序独立计算。

## 6. 引擎、界面与验收

Rust 世界引擎持有权威状态。事件记录游戏日、事件 ID、居民或设施 ID、变化前后值及触发原因，归因到上一条事件时保存来源 ID。每项资源变化必须对应一笔可核对的流水。日终画面显示日期、天气、在世人数、库存、未满足配给、已接受和空缺班次、设备状况及当天事件。发生停产时，玩家可以从设施状态追到失效的工时、供电或设备条件。

ETA 在 M3 接入认知层，接收只读的情境快照，返回结构化行动提案。提案由世界引擎验证权限、库存、设备条件和居民同意后结算。日常生活循环由规则推进。

| 阶段 | 可交付验收 |
| --- | --- |
| M0 · 确定性世界 | 固定种子生成 100 名居民。CLI 可自动推进 1、10、100、500 日，打印摘要并导出日志。同一版本、场景和种子下，500 日终态与事件序列完全一致 |
| M0 · 守恒与因果 | 每日逐项核对期初、产出、转入、消耗、转出和期末。库存保持非负，居民状态保持在合法范围内。用可控场景复现断电停水、饮水短缺、疲劳拒班、工伤和维修复工 |
| M1 · 自主协调 | 三个组织持有各自的成员名册。居民按规则提出或表决备用供电与农渔排班提案，获批规则反映到次日调度。同班完工积累熟悉度并影响搭班顺序，居民保有拒班权。500 日回放可核对表决、排班和资源变化 |
| M2 · 玩家交互 | 玩家以一名居民的身份查看获准信息、申请加入组织，并提交一项现有组织规则的修改提案，下一轮排产反映生效结果 |
| MVP · 备件加工 | 玩家能用普通加工设备补充一类水泵备件 |
| M3 以后 · 认知与原型评估 | ETA 可根据聚落情境提出结构化行动。模拟可保存、恢复并继续。评估一次 500 日运行的时间、事件分布、居民生存、库存变化和模型开销 |
